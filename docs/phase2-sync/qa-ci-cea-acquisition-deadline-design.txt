2. Why the scope is deliberately narrow

The controlled triage called the real inner openRouteAttempt while a real withStoreLock operation held the same source directory for 140 ms. The original 100 ms request budget expired while the 300 ms pass still had time. Its exact native error lacks the filesystem-acquisition suffix and is the line-213 queue throw. The holder and waiter shared localQueues. No HTTPS request began.

A queue rejection passes through withStoreLock's finally before reaching the caller. The finally clears the timer and resolves this waiter's queue placeholder. It never schedules the rejected operation to run after the predecessor releases. Queue deletion remains chained behind the predecessor, preserving exclusion. There is no descriptor or namespace from this acquisition to release. openRouteAttempt's catch removes any entry/listener before rethrowing; for this origin the registration callback never ran and its watcher timer was never installed. That is the proof needed for the selected transient.

This proof concerns this rejected invocation, not the health, release outcome or quiescence of a different holder or the enclosing reconciliation attempt. Subsequent actual admission still performs all current store/route validation. A timeout cannot prove the ledger healthy; it also cannot excuse an observed ledger or cleanup error.

Do not type every checkAcquisition throw as safe. A check occurs after candidate creation and after canonical installation, as well as before ownership exists. More decisively, reaperSnapshot returns null for malformed/unknown/unsafe ownership and reclaimDeadLock also returns for inconclusive/live ownership. Those paths eventually reach the SAME raw deadline. Successful disposal of this invocation's candidate does not establish that a foreign canonical namespace is valid. No existing typed outcome carries that distinction.

A broader filesystem-acquisition contract would need fresh provenance distinguishing ordinary verified contention from absent/racing/unverifiable ownership, no observed operational error, no protected callback, completed proven-owned name cleanup, every required managed flush, and every descriptor close without even a recoverable first-close rejection. Installed authority would need the existing exact-inode/bytes release and directory flush; closeHandles alone is insufficient. Never inspect/unlink L after successful final unlink, because a successor may own it. A compound failure must remain compound even if cleanup later succeeds. That broader protocol is unnecessary for this proven queue trigger and should not be authorized under this smallest gate.

The later startCommunication await at client line 107 also waits for a lock, but it follows successful attempt registration and starts the client's controller/timer. Keep it excluded. Attempt.close is synchronous and does not await a watcher already in flight. No general attempt-quiescence claim is justified here. The other store deadline prechecks and outer reconciliation admission remain excluded too.
