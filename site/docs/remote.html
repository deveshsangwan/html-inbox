Export and publish static snapshots

A snapshot contains the complete library at a point in time. It is separate from the live loopback, LAN, or Tailscale viewer and does not move your local documents.

Export without a provider

html-inbox export --out ./html-inbox-export

The command builds a static inbox with browser-side search, original document bytes, a manifest, and security policy metadata. It prints the document count, snapshot hash, and inbox path /i/<capability>/. The site's root deliberately has no inbox listing.

The output must be outside HTML_INBOX_HOME and cannot contain it. A recognized prior export can be replaced through staging; an unrelated directory is refused. Protect the output and its parent, since staging and backup paths can contain the full snapshot.

For automation, use --json. Normally let the exporter generate the 128-bit capability. --capability can reproduce a known path, but it must be a canonical 22-character base64url encoding of exactly 16 bytes. 

html-inbox export --out ./html-inbox-export --json

A generic host must install the policies recorded in security-headers.json on every corresponding route and alias. Copying HTML alone does not install those response headers. Opening files through file:// does not provide the served CSP. The built-in Cloudflare adapter applies the required hosting policies.

Anyone who receives the capability URL can read and reshare the complete snapshot. It is an unlisted bearer link, not a login or recipient authentication. Browser history, screenshots, copied links, and logging can expose it.

Configure your Cloudflare Pages project

Authenticate the pinned Wrangler CLI once using its browser login. 

npx --yes wrangler@4.86.0 login

For non-interactive commands, supply CLOUDFLARE_API_TOKEN with Account / Cloudflare Pages / Edit permission through the environment. The account ID is explicit configuration, not a secret. HTML Inbox does not store the token in its records or pass it as a command argument.

Use a dedicated Pages project. Replace the placeholders with your 32-character hexadecimal Cloudflare account ID and intended project name. 

html-inbox remote init \
  --account <cloudflare-account-id> \
  --project <pages-project-name>
html-inbox remote publish
html-inbox remote status

remote init creates a missing project. An existing project requires --adopt because publishing replaces its complete contents. The default production branch is main; --branch selects another branch only when it agrees with the Pages project's production branch. 

html-inbox remote init \
  --account <cloudflare-account-id> \
  --project <existing-pages-project> \
  --adopt

Inspect the account and project before adoption. The export ownership marker is not proof that a remote project belongs to HTML Inbox.

Publish later changes

remote publish deploys every current local document as a complete new snapshot and prints the production capability URL. Local publishing and deletion do not deploy automatically. 

html-inbox remote publish
html-inbox remote status --json

The local library remains the source of truth. Remove documents you do not intend to share before publishing. Open the production capability URL, test search and a document, and share that path rather than the site's root.

Keep the snapshot within hosting limits

The current Cloudflare adapter checks a maximum of 20,000 upload files and 25 MiB per file before deployment. Generated viewer, document, manifest, and policy files all contribute to the upload, so file count is not the same as document count. Increasing HTML_INBOX_MAX_BYTES can let a local document exceed the remote file limit.

The adapter also bounds generated _headers rules and lines. If a snapshot cannot fit the supported hosting policy, publishing fails rather than dropping security headers. Reduce the library or document size before retrying.

Recover an ambiguous operation

Remote mutations record durable intent under the private inbox before the external request. A timeout can occur after Cloudflare accepted a deployment. Reconcile the preserved operation instead of repeatedly starting a new publish. 

html-inbox remote status
html-inbox remote reconcile
html-inbox remote status

Reconciliation checks deployment history for the operation ID and snapshot digest before retrying. If ambiguous project creation discovers an existing project, reconciliation requires --adopt after you inspect the target. Lock recovery never grants adoption automatically.

Recover a terminated remote command

A killed command can leave remote/mutation.lock. After confirming that the previous command and its child processes exited, use the same machine and inbox to request explicit recovery. 

html-inbox remote status
html-inbox remote reconcile --recover-lock
html-inbox remote status

Recovery needs a complete valid lock record and an OS check that its PID no longer exists. A live or reused PID, malformed record, permission failure, or inconclusive check blocks recovery. The CLI sends no termination signal and does not use lock age as proof.

For a malformed lock, an interrupted recovery guard, or a home shared by multiple machines, stop all commands using that home and verify their processes exited. Back up the complete private remote directory. Remove only mutation.lock and mutation.lock.recovery, preserving state.json, operation.json, and work. Then run remote reconcile. If you cannot establish that all commands stopped, leave the locks in place.

Revoke the production link

html-inbox remote revoke

Revoke asks for confirmation, then replaces the production route with a new undisclosed empty capability. Use --yes for non-interactive operation; --json provides structured output. 

html-inbox remote revoke --yes --json

Revocation does not erase older immutable Cloudflare deployment URLs, recipient copies, or exports. Prune sensitive historical deployments in Cloudflare before treating old content as inaccessible. Deleting local documents or removing local remote state does not revoke an already deployed snapshot.

See remote security limits and the source recovery guide for the longer manual recovery procedure.
