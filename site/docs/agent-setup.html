HTML Inbox documentation

Set up your agent

Start with the main skill to let your agent publish HTML and manage the live viewer. The current skills installer needs Node.js 22.20.0 or newer and npm. The HTML Inbox CLI itself supports Node.js 20 or newer. A source checkout and a global CLI installation are optional.

Install the main skill

npx skills add deveshsangwan/html-inbox --skill html-inbox -g

The skill supplies agent instructions for publishing, viewer lifecycle, LAN, Tailscale, and boot-service setup. The npm html-inbox package supplies the executable that performs those operations.

The installers are independent. Adding a skill does not install a global CLI, and installing the CLI does not add a skill. Manual terminal users can install the CLI first and add agent instructions later.

Choose project scope and target agents

-g installs in your user directory for use across projects. Omit it to install in the current project. The installer lets you choose target agents. Use --agent to choose explicitly, such as codex or claude-code. 

npx skills add deveshsangwan/html-inbox --skill html-inbox --agent codex

Add -g to that command if you want the same agent selection globally. Add --yes only when you want to skip installer confirmation prompts. Follow your agent's instructions for loading newly installed skills. Choose a supported agent explicitly for unattended installation, and check the installer's per-agent results.

List available skills in the public repository without installing them:

npx skills add deveshsangwan/html-inbox --list

To inspect installed project skills, use npx skills list. Use npx skills list -g for global installations. See the official skills CLI reference for supported agents and installer options.

Resolve the CLI on first use

Ask your agent to publish a finished HTML file, for example, "Publish ./report.html to HTML Inbox with the title Project update and type report." The installed skill checks the CLI before publishing.

A successful html-inbox --version returning a single stable 0.2.x version selects the installed executable. A missing, failed, malformed, older, prerelease, or newer minor or major version selects the tested npm fallback. The skill checks that the fallback reports exactly 0.2.0 before continuing. 

npx --yes html-inbox@0.2.0 --version

The fallback runs the package through npm without installing a global command. It needs registry access or an already cached package. The skill uses the same selected command prefix throughout the operation. A download or startup failure must be resolved before the agent can report a successful document URL.

HTML_INBOX_HOME, HTML_INBOX_PORT, and HTML_INBOX_TAILSCALE_COMMAND keep their existing values. First viewer startup uses loopback; later publishing and viewer starts preserve saved exposure settings. Ordinary publishing does not add LAN or Tailscale flags. The printed URL is authoritative.

A boot service needs deliberately installed Node and CLI executables at stable absolute paths. An npm cache entry from the fallback is not a durable service installation. If you choose boot startup, follow the explicit administrator setup guide. Ordinary skill use does not require this installation.

Add the optional Cloudflare skill

npx skills add deveshsangwan/html-inbox --skill html-inbox-remote -g

html-inbox-remote handles Cloudflare Pages setup, snapshot publishing, recovery, and revocation. It installs independently of the main skill and uses the same CLI-resolution rules. Omit -g for project scope, and use --agent as above.

Cloudflare publishes the complete library as a static snapshot. Its unlisted capability URL is a bearer link: anyone with it can read and reshare that snapshot. It is separate from the live viewer served on your LAN or through Tailscale. Read static and remote publishing before setup.

Update skills separately from the CLI

Update the global main skill by name:

npx skills update html-inbox -g

For a project installation, run this from that project instead:

npx skills update html-inbox -p

Substitute html-inbox-remote to update the optional Cloudflare skill. Omitting the name updates all skills in the selected scope. Interactive npx skills update without scope flags prompts for project, global, or both. --yes skips that prompt and auto-detects project scope when in a project, otherwise global. skills check is an update alias, not a read-only check. These commands do not update the npm CLI.

You can also rerun the original individual skills add command with the same scope and agent selection. Refresh the complete skill directory, including bundled references and scripts, so CLI-resolution guidance stays together. The fallback stays pinned until an updated skill changes it. See the official update reference.

Before changing CLI versions, stop an older viewer using the executable that started it. Stop a foreground viewer with Ctrl-C. The new CLI refuses unverifiable older process records. Confirm the viewer has stopped before installing the new version. Follow CLI update instructions for npm and service update instructions if you use boot startup. Updates preserve stored documents and saved exposure settings.
