HTML Inbox documentation

Read the inbox on your LAN

Choose LAN exposure explicitly when other devices should read the live library. Every device that can reach the listening port can browse, search, and open every document.

Start LAN mode

Stop any existing viewer for this inbox, then start LAN mode.

html-inbox viewer stop
html-inbox viewer --lan

The default LAN bind address is 0.0.0.0. The CLI reports concrete IPv4 interface URLs such as http://192.168.1.20:3217, not the wildcard address. Open a reported URL on another device connected to the same network.

LAN mode has no password, login, or shared reader token. Traffic uses HTTP. Choose this mode only when you trust everyone who can reach the port to read the complete library, including document metadata.

Choose an address and port

On a server with several interfaces, bind the IP address you intend to expose. Replace this example with an address assigned to your server. 

html-inbox viewer --lan --host 192.168.1.20 --port 4321

--host accepts an IPv4 or IPv6 address, not a DNS name. Scoped IPv6 addresses containing % are not supported. --port overrides the port environment variable and saved configuration.

Use --host :: for an IPv6 wildcard bind. The CLI reports usable IPv6 and IPv4 interface URLs where available, with brackets around IPv6 authorities. Actual dual-stack availability depends on the operating system. Loopback, scoped, and multicast addresses do not become advertised network URLs.

A wildcard viewer refreshes accepted interface authorities when addresses change. Status and publishing derive current interface URLs. If there are no usable network addresses, they give an actionable error rather than printing an old address. Select an explicit assigned IP with --host when that is appropriate.

Check network reachability

The operating system firewall and your network determine reachability. HTML Inbox does not change either. Confirm that the server owns the printed IP, that the client can route to it, and that the selected TCP port is permitted for the intended network.

Do not forward the LAN port to the public internet. For encrypted access within an existing tailnet, use Tailscale mode. HTML Inbox has no general reverse-proxy mode: arbitrary Host or forwarded-host headers are not accepted.

Keep management local

LAN readers can browse and search the inbox and open documents. They cannot publish, delete, start, stop, or configure a service through the browser. Run those commands locally under the account that owns the inbox. 

html-inbox publish ./report.html --title "New report" --type report
html-inbox viewer status

Publishing reuses the exposed viewer and prints a network document URL. Other readers see the new record immediately. The original sandbox, CSP, metadata escaping, storage checks, and Host validation continue to apply.

Host validation limits request authorities; it does not authenticate readers. Client-supplied forwarding or Tailscale identity headers grant no access. Public reader health is anonymous, and process identity remains on a separate protected local control path.

Stop sharing

html-inbox viewer stop
html-inbox viewer --loopback

Stopping preserves the documents. Starting with --loopback changes the saved mode for later starts and publishing. If a boot service is installed, update or uninstall its definition too; ordinary viewer stop does not remove boot configuration.
