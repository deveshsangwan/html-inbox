HTML Inbox documentation

Start the viewer before login

Install boot configuration explicitly. Linux uses a systemd system service; macOS uses a LaunchDaemon. Both run the viewer as a selected normal user before anyone logs in.

Choose stable paths and an account

Install Node.js 20 or newer and HTML Inbox at paths that will remain available across reboot. From the intended user's shell, locate the executables. 

command -v node
command -v html-inbox

The following examples use Alice's resolved absolute paths. Replace them with your own. The CLI records the actual Node binary and package entry path, so moving a package or deleting a Node version directory requires service reinstallation.

Linux requires systemd as the system service manager. macOS uses the system launchd domain. Windows supports the ordinary CLI and viewer, but these service commands do not install Windows boot services.

Install a loopback service

sudo /absolute/path/to/node /absolute/path/to/html-inbox \
  viewer service install --user alice --loopback --port 3217

Installation requires administrator privileges. The viewer itself cannot run as root. --user selects the normal account; a sudo invocation may also use SUDO_USER. A root shell without a selected normal account must supply --user.

The default library is the selected user's ~/.html-inbox, even if sudo sets HOME to /root. Stop an existing detached viewer for that inbox before installing the service. Installation reports success only after the manager PID matches a healthy viewer.

Normal viewer startup never installs or changes a boot service. A user's login service would start too late; HTML Inbox installs a system service or LaunchDaemon for the before-login requirement.

Keep a custom inbox

Use the same absolute inbox path for installation, status, and removal. Its parent must already exist. An existing inbox must belong to the selected user; installation can create a missing inbox for that user without recursively changing document ownership. 

sudo env HTML_INBOX_HOME=/home/alice/inboxes/reports \
  /absolute/path/to/node /absolute/path/to/html-inbox \
  viewer service install --user alice --lan --host 0.0.0.0 --port 4321

HTML_INBOX_HOME=/home/alice/inboxes/reports html-inbox viewer service status

Choose --loopback, --lan, or --tailscale deliberately. If networking options are omitted, installation uses the selected inbox's saved configuration. LAN still trusts every reachable reader.

Use Tailscale at boot

Configure and sign in to Tailscale separately. The selected normal account must be able to use the existing client and Serve at boot. An executable override helps when sudo's PATH differs from the user's PATH. 

sudo env HTML_INBOX_TAILSCALE_COMMAND=/absolute/path/to/tailscale \
  /absolute/path/to/node /absolute/path/to/html-inbox \
  viewer service install --user alice --tailscale --port 3217

The service preserves the absolute Tailscale executable. It resolves the connected hostname on startup, rather than freezing an old hostname in the definition. Missing connectivity, prerequisites, or permissions can prevent readiness.

Understand the preserved configuration

The definition records the selected user, inbox, port, exposure, host, Node and CLI paths, and Tailscale path when needed. It sets the user's real HOME and a PATH assembled from resolved directories. It preserves NODE_OPTIONS, NODE_EXTRA_CA_CERTS, SSL_CERT_FILE, and SSL_CERT_DIR if present during installation. Other shell variables and secrets are not copied.

Definitions are readable for status checks. Do not put secrets in those preserved values. The inbox must also be accessible before login; a home directory encrypted or mounted only after login cannot meet this boot requirement. The installer does not configure mounts or encryption.

Only one boot service definition is managed per machine. Commands for another inbox refuse to replace or remove it. Reinstalling matching settings is idempotent; changing settings updates a verified owned definition. Unrelated, modified, symlinked, and hard-linked definitions are refused. Failed operations attempt rollback and report incomplete rollback explicitly.

Check status and logs

html-inbox viewer service status

Status checks both the service manager and private viewer readiness. Status and readiness execute the CLI under the selected normal account, including its Tailscale checks. The administrator process does not execute an inbox-configured Tailscale path as root.

Platform Definition and diagnostics
Linux /etc/systemd/system/html-inbox-viewer.service. Inspect journalctl --unit=html-inbox-viewer.service, with administrator access if needed.
macOS /Library/LaunchDaemons/com.html-inbox.viewer.plist. Inspect launchctl print system/com.html-inbox.viewer and the selected inbox's viewer.log.

Linux writes service output to the journal. The macOS foreground worker opens its private log after switching to the selected user. Neither the installer nor boot manager opens an inbox log as administrator. An unsafe log path fails startup; run foreground mode as the selected user to inspect and correct the file error.

Both services restart failed processes and allow 120 seconds for graceful shutdown, including scoped Tailscale cleanup. Commands waiting for manager stop or restart allow 150 seconds.

Remove boot startup

sudo /absolute/path/to/node /absolute/path/to/html-inbox \
  viewer service uninstall --user alice

Uninstall stops and disables the owned service and removes its definition. It preserves documents, private records, and logs. Include the same HTML_INBOX_HOME for a custom library.

viewer stop does not remove boot configuration. Use service uninstall when you want to prevent startup at the next boot or a later manager restart.

Update a service installation

Uninstall the service with the old CLI before upgrading, then install the updated CLI and reinstall the service as the same normal account with the intended inbox and exposure. This avoids incompatible old process records and stale executable paths. 

sudo /absolute/path/to/node /absolute/path/to/html-inbox \
  viewer service uninstall --user alice
npm install --global html-inbox@latest
sudo /absolute/path/to/node /absolute/path/to/html-inbox \
  viewer service install --user alice --loopback --port 3217

Run npm under the account and installation method you normally use. Replace the final example's networking options with the exposure you intend to preserve.
