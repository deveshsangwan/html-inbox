HTML Inbox documentation

Start with one HTML file

Set up your agent or install the CLI for terminal use, then publish a report to your local library. The skills installer needs Node.js 22.20.0 or newer; the HTML Inbox CLI needs Node.js 20 or newer. Both use npm. You do not need a source checkout.

Set up your agent

Start with the main skill when you want your agent to publish files and manage the viewer. It installs agent instructions for your user across projects.

npx skills add deveshsangwan/html-inbox --skill html-inbox -g

The skill and CLI installers are independent. Adding a skill does not install a global executable. On first use, the skill reuses a working, stable html-inbox 0.2.x CLI or selects npx --yes html-inbox@0.2.0 for the operation. The fallback needs registry access or a cached package and preserves your existing viewer settings.

See agent setup for project installation, target agents, the optional Cloudflare skill, and updates. If you want to run commands yourself, install the CLI below. You can add a skill later.

Install the CLI for terminal use

Install the latest published package from npm. These docs describe the 0.2 release, including background viewers and live self-hosting. Check your installed version if a command is unavailable. 

node --version
npm install --global html-inbox@latest
html-inbox --version
html-inbox --help

For occasional use, npx html-inbox --help runs the npm package without a global install. Installing the npm package does not install agent skills. The examples in this guide use the installed html-inbox command. The CLI supports Linux, macOS, and Windows. Boot service installation supports Linux with systemd and macOS.

Publish your first document

Save a UTF-8 file named report.html. Here is a complete document you can use. 

<!doctype html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <title>Project update</title>
  <style>body { font: 18px/1.6 system-ui; max-width: 42rem; margin: 3rem auto; padding: 0 1rem; }</style>
</head>
<body>
  <h1>Project update</h1>
  <p>The migration is ready for review.</p>
</body>
</html>
html-inbox publish ./report.html --title "Project update" --type report

Open the document URL printed by the command. HTML Inbox validates the file, stores its original bytes, and starts or reuses the viewer. A new library lives at ~/.html-inbox and first startup listens on 127.0.0.1:3217.

The viewer runs in the background and keeps running when the terminal closes. Publish more files to add them to the same library. Every publish creates a new document with its own ID.

Find and manage documents

html-inbox viewer
html-inbox list
html-inbox viewer status

viewer prints the inbox URL. Search in the browser by title, type, or original file name. Use a document ID from list when you want to remove a document. 

html-inbox delete <document-id>
html-inbox viewer stop

Deletion asks for confirmation in an interactive terminal. Stopping the viewer preserves your library. Start it again whenever you need it.

Before storing sensitive reports or sharing a library, read security and storage. LAN mode has no login, and remote snapshot URLs are bearer links.

Update an installation

Update agent instructions separately using the skill update instructions. Before changing CLI versions, stop an old viewer using the executable that started it. The 0.2 private process-control protocol differs from earlier releases, and the new CLI refuses to signal a process it cannot verify. Confirm the old viewer has stopped before installing the new version. 

html-inbox viewer stop
npm install --global html-inbox@latest
html-inbox --version
html-inbox viewer

For an old foreground viewer, stop it with Ctrl-C. If you installed a boot service, uninstall and reinstall it during the update so its executable paths remain correct. Upgrading the CLI preserves your documents. Saved exposure settings continue to apply.
