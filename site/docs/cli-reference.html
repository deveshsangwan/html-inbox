HTML Inbox documentation

CLI reference

This reference describes 0.6.0. Library commands resolve one destination from explicit flags, environment, or the configured default. Run html-inbox --help for the actual installed command set and html-inbox --version to identify the release.

Live UI deletion is available in running 0.5.x and 0.6.x readers. The skill fallback is published 0.5.0, including deletion, copying and named inboxes but no managed sync. Review saved exposure and hub mounts, the 0.5.0 permission change, and 0.6.0 opt-in enrollment before upgrading.

Help and version

html-inbox --help
html-inbox -h
html-inbox --version
html-inbox -v

Help and version are top-level commands. Unknown commands and unsupported flags return an error. Publishing and lifecycle control have no reader HTTP endpoints. Live readers can permanently delete individual documents.

Library selection

Library commands accept --inbox <name> and absolute --home <path>. Explicit selection overrides the entire environment tier, then HTML_INBOX_NAME / HTML_INBOX_HOME override the configured default. A name and home in the same tier must match. Unknown names, missing roots, and changed identities fail.

With entries and no binding or default, stdin, stdout, and stderr must all be TTYs for the picker. Enter an exact name or #N row; :q, Ctrl-C, or EOF cancels. The choice applies once and never saves a current inbox. Even one entry requires a choice. Scripts, redirected streams, and JSON mode fail with guidance instead. With no entries or bindings, legacy ~/.html-inbox first use remains. See selection details.

Named inbox catalog

html-inbox inbox create <name> --home <absolute-path> [--json]
html-inbox inbox register <name> --home <absolute-path> [--json]
html-inbox inbox list [--running] [--json]
html-inbox inbox default <name>
html-inbox inbox default --clear

Create initializes a new library; register names an existing valid library in place. Names use 1-63 lowercase letters, digits, underscores, or hyphens, start with a letter or digit, and exclude reserved filenames. Bindings capture canonical homes and UUIDs. List inspects registered sources read-only and shows stopped, unavailable, or incompatible entries. --running includes only privately verified running viewers; it does not discover unregistered libraries or select a destination. --json includes local paths. Defaults affect future unbound operations only; inbox default has no JSON flag.

Local reading hub

html-inbox hub init --config <absolute-path> --inbox <name> [--inbox <name> ...] [--name <title>]
html-inbox hub --config <absolute-path> [--port <port>] [--loopback | --lan] [--host <ip>]

Init captures 1-128 explicit source bindings in a new config under an existing canonical parent directory; it refuses replacement. Default title is Reading hub. Startup runs in the foreground on loopback port 3218, prints a reader URL, and stops with Ctrl-C. Sources must be on this machine and accessible to the same OS account. Every reachable reader can read every mount, including stopped or private source viewers. Membership stays fixed; new catalog entries do not join. Hubs do not configure Tailscale or boot services, and neither hub command accepts --json. See hub operation.

Documents

html-inbox publish <file.html> --title <title> --type <type> [--json] [--wait-ms <ms>] [--request-timeout-ms <ms>] [--target-peer <uuid> --target-inbox <uuid>]
html-inbox list [--json]
html-inbox delete <id> [--force] [--json]

publish requires one regular UTF-8 .html or .htm file and both metadata flags. Unenrolled publication prints a document URL, or JSON with url, inbox and home. Managed publication has the saved/delivery result with viewer.url. Its timing/target flags are rejected for unenrolled libraries; target overrides must be paired. It does not accept stdin or JSON input. Title and type are non-empty text labels, limited to 200 and 64 characters.

list prints metadata in newest-first order, as a readable table or JSON. delete requires the document ID, asks for confirmation unless --force is supplied, and reports metadata plus reclaimed bytes with --json. Managed deletion reports reclaimedBytes: 0: originals sign terminal state and imports are suppressed locally while bodies remain. Non-interactive or JSON CLI deletion needs --force.

Appearance preferences

html-inbox preferences [--appearance <system|light|dark>] [--json]

Available since 0.2.1. Read or set the default appearance stored in the selected inbox. The default is system; readers can override it in their own browsers. --json prints the resolved preference. Reading without --appearance does not create a preference file. Static exports capture the saved default when created.

In a live viewer or hub, choose Delete in a list row's three-dot menu or in document options. The confirmation defaults to Cancel and identifies the title, filename, and inbox. Every reachable live reader can delete, without a startup grant or reader login, on loopback, LAN, and Tailscale. Static exported or hosted copies remain read-only.

Viewer

html-inbox viewer [--foreground] [--loopback | --lan | --tailscale] [--host <ip>] [--port <port>]
html-inbox viewer status [--json]
html-inbox viewer stop [--json]
Option Behavior
--foreground Stay attached for debugging or an external manager. Default startup is detached and returns after readiness.
--loopback Choose local-only exposure. Default bind 127.0.0.1.
--lan Choose live LAN readers. First LAN startup or a switch from another mode binds 0.0.0.0 without an explicit host. Existing LAN configuration retains its saved host, including with explicit --lan. All reachable readers are trusted.
--tailscale Use the existing client's HTTPS Serve root on 443 with a 127.0.0.1 backend.
--host <ip> Select an IPv4 or IPv6 bind address. No DNS names or IPv6 scope identifiers. Loopback mode needs a loopback IP; Tailscale needs exactly 127.0.0.1.
--port <port> Integer 1 through 65535. Overrides HTML_INBOX_PORT. In Tailscale mode this is the backend port.

Exposure flags are mutually exclusive. Omitted networking options reuse the inbox's saved configuration, or loopback port 3217 on first startup. Stop the active viewer before changing configuration. status and stop accept no startup flags and print readable text by default. Add --json for machine-readable fields; a successful status command can still report a stopped, conflicting, or incompatible viewer.

Boot services

html-inbox viewer service install [--user <normal-user>] [--loopback | --lan | --tailscale] [--host <ip>] [--port <port>] [--json]
html-inbox viewer service uninstall [--user <normal-user>] [--json]
html-inbox viewer service status [--user <normal-user>] [--json]

Install and uninstall require administrator privileges on Linux with systemd or macOS. The viewer runs as the selected normal account. --user or sudo's SUDO_USER selects that account; root itself is refused. Only install accepts networking options. All service commands print readable text by default; use --json for automation.

Use the same absolute --home or HTML_INBOX_HOME for a custom inbox. Elevated named selection uses the invoking account's catalog; resolve the normal user's intended home before sudo. There is still one fixed boot-service definition per machine. See boot services for stable executable paths, permissions, and sudo examples.

Static export

html-inbox export --out <directory> [--capability <value>] [--json]

--out is required and must be outside the inbox, must not contain it, and must not be a filesystem root. Recognized earlier exports may be replaced; unrelated directories are refused. Optional capability values must encode exactly 128 bits in canonical 22-character base64url form. Omit the flag to generate a capability.

Cloudflare remote commands

html-inbox remote init --account <id> --project <name> [--branch <name>] [--adopt] [--json]
html-inbox remote publish [--json]
html-inbox remote status [--json]
html-inbox remote reconcile [--adopt] [--recover-lock] [--json]
html-inbox remote revoke [--yes] [--json]
Command or option Behavior
remote init Configure one Pages target. Account ID is 32 hexadecimal characters. Project names use 1 to 63 lowercase letters, digits, or hyphens, with a letter or digit at each end.
--branch Default main. Must agree with the Pages production branch. Uses 1 to 128 safe characters; invalid traversal or leading/trailing separators are refused.
--adopt Explicitly accept an existing Pages project for complete-content replacement. Reconciliation may need separate adoption after ambiguous creation.
remote publish Deploy eligible local originals as a static snapshot. Synced imports, detached imports and fork-inherited originals are excluded.
remote status Read configured target, deployment state, and preserved operation intent.
remote reconcile Inspect deployment history and recover preserved intent before retrying.
--recover-lock Verify and replace a valid abandoned remote mutation lock. No termination signal or age-based takeover.
remote revoke Rotate away from the production capability route. Older immutable deployment URLs can remain readable.
--yes Confirm revoke without an interactive prompt. Required for non-interactive revoke.

JSON remote output includes capabilities and deployment URLs. Protect captured output. Authentication comes from Wrangler's existing login or the Cloudflare token environment, not an HTML Inbox password.

Output and automation migration

Since 0.3.0, viewer status/stop and service commands require --json to retain machine-readable output. Plain document and catalog lists are readable tables. Unenrolled plain publish, detached viewer startup, and hub startup retain URL-only stdout. Named context, picker text, and warnings go to stderr. JSON never prompts or grants approval; CLI deletion requires --force and revoke requires --yes.

Managed publication prints a multiline Saved locally / Delivery / reader URL / onward receipt. Its JSON has local.durable, document identity, delivery, worker, and the optional reader link at viewer.url. Exit 0 means confirmed intended-server custody or unconfigured local-only storage; 2 means durable pending, 3 durable blocked, and 130 cancellation after save when a saved result is present. Exit 1 covers validation, persistence or uncertain durability. Preserve the saved report, intended target and obligations; nonzero delivery status is not permission to duplicate publication or choose another destination. Viewer readiness is separate. Inspect uncertainty before retrying when no saved evidence is present.

Published 0.2.x viewer and service commands output JSON without that flag. Check actual help before using new flags with an older CLI. The published 0.5.0 skill fallback supports named selection, hubs, and reader copy controls, but has live-reader deletion but no managed sync. See upgrade steps and the canonical CLI resolver rules.

Managed sync commands and limits

Managed sync is an explicit POSIX-only format upgrade of a named inbox. Ordinary Windows libraries remain supported. Use top-level html-inbox --help for command help; per-subcommand help is not provided. Every sync variant accepts --json. Without it, ordinary sync results are pretty JSON; supervisor render prints definition text. Managed publish uses its separate plain receipt. Preserve the selected inbox for online commands. Offline restore/fork requires explicit --home rather than --inbox. 

html-inbox sync enroll --inbox research --yes --json
html-inbox sync configure --inbox research --config /absolute/private/runtime.json --json
html-inbox sync status --inbox research --document LOCAL_ID --json
html-inbox sync mapping add --inbox research --config /absolute/private/mapping.json --json
html-inbox sync mapping remove ROUTE_UUID --inbox research --revision CURRENT --json
html-inbox sync mapping reconnect ROUTE_UUID --inbox research --revision CURRENT --config /absolute/private/mapping.json --json
html-inbox sync target set DESTINATION_UUID --peer PEER_UUID --inbox research --json
html-inbox sync target clear --inbox research --json
html-inbox sync run --route ROUTE_UUID --inbox research --json
html-inbox sync retry --route ROUTE_UUID --inbox research --json
html-inbox sync pause --inbox research --json
html-inbox sync resume --inbox research --json
html-inbox sync worker enable --inbox research --json
html-inbox sync worker start --foreground --inbox research
html-inbox sync worker startup --inbox research --json
html-inbox sync worker status --inbox research --json
html-inbox sync worker stop --inbox research --json
html-inbox sync worker disable --inbox research --json
html-inbox sync worker wake --inbox research --json
html-inbox sync worker supervisor render --inbox research --platform systemd --user NORMAL_USER
html-inbox sync worker supervisor status --inbox research --definition /absolute/installed-definition --json
html-inbox sync restore inspect --home /canonical/copied-home --json
html-inbox sync restore quarantine --home /canonical/copied-home --expect-inbox OLD_UUID --yes --json
html-inbox sync fork --home /canonical/copied-home --expect-inbox OLD_UUID --yes --json

Inspect has no --expect-inbox flag; quarantine/fork require it and explicit consent. Mapping remove/reconnect requires the expected current revision. Removal reports removed and quiesced separately and can exit 3 with quiescence false. Retained copies stay detached. Reconnect needs matching fresh endpoint revisions and trusted terminal history before live reattachment.

Worker enable persists enablement before startup, even if startup fails. Start requires enablement; startup skips a disabled worker. Stop ends the current owned process but keeps enablement; later authorized work can restart it. Disable persists disabled state before stopping. Wake requires enablement and starts or reuses the owned runtime before requesting catch-up. It does not enable a disabled worker. Run performs one bounded pass and does not enable automatic sync. Pause stops locally initiated work, while authorized incoming pushes may continue. Resume does not clear permanent blocks; explicit route retry clears retry/backoff state. Replacing a credential file alone does not reset a blocked route.

Default foreground wait is 30,000 ms, absolute request budget 5,000 ms, periodic reconciliation 30,000 ms and pass budget 60,000 ms. Managed publish accepts --wait-ms from 100 to 300,000 and --request-timeout-ms from 100 to 30,000. Paired --target-peer and --target-inbox UUID flags pin only that publication; unenrolled publish rejects these managed flags. Runtime reconcile bounds are 1,000–300,000 ms and pass bounds 100–60,000 ms. Transient retries start at one second, cap at five minutes with jitter, and block after twenty consecutive failures. Status and wake do not reset them. No listener, target or enabled worker exists by default. Clearing an intended target changes foreground waiting, not existing obligations or approved background routes. Local-only output does not prove that replication is disabled.

Provision receiving enrolled inboxes, matching endpoint route IDs and revisions, approved origin/key/epoch scopes, credentials and TLS explicitly. Runtime JSON requires schemaVersion, intendedTarget, listener, timings, credentials, trust and tls; use null for unconfigured listener/target. Local references resolve canonical absolute private files. Tokens are canonical base64url for 32–96 random bytes. TLS uses system trust or an explicit CA, never certificate bypass. Ingestion binds an explicit unicast literal IP; viewer LAN wildcards and Tailscale reader Serve are separate. Exact JSON examples are in the runtime and mapping interface. Read the enrollment, rollback and retention limits before mutation.

Environment variables

Variable Default and purpose
HTML_INBOX_NAME Registered library name in the environment selection tier.
HTML_INBOX_CATALOG_HOME Private per-user catalog, default ~/.config/html-inbox. Independent of the selected library.
HTML_INBOX_HOME Library and private operational state in the environment selection tier. With no binding, default, or registered entries, the legacy home is ~/.html-inbox. Relative paths resolve against the working directory. Unconfigured legacy boot operations use the selected normal account's home.
HTML_INBOX_PORT An explicit port override. Without it, use the saved port or 3217 on first startup. Integer 1 through 65535.
HTML_INBOX_MAX_BYTES 10485760, or 10 MiB. Positive safe integer byte limit for ordinary publish and hub content reads. A lower input limit can reject managed publication, but a larger value cannot raise managed storage's fixed 10 MiB body cap. Descriptors, ledger metadata and canonical record counts have separate bounds.
HTML_INBOX_TAILSCALE_COMMAND Existing Tailscale executable path; otherwise resolve tailscale on PATH. Explicit overrides apply to startup, status, and cleanup; the successful absolute path is saved.
CLOUDFLARE_API_TOKEN Optional non-interactive Wrangler credential with Account / Cloudflare Pages / Edit permission. No token is stored in HTML Inbox records.

For boot definitions, selected NODE_OPTIONS, NODE_EXTRA_CA_CERTS, SSL_CERT_FILE, and SSL_CERT_DIR values may be preserved. They are visible in the definition and must not contain secrets. Internal worker variables are not user configuration.

Unix-shell environment prefixes in these docs are not PowerShell syntax. Set a value there with $env:HTML_INBOX_HOME = 'C:\Users\Alice\.html-inbox', then run the CLI normally.
