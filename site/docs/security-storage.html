HTML Inbox documentation

Protect the library and its readers

HTML Inbox is local-first single-user software. Reader exposure is deliberate, documents stay untrusted, and filesystem privacy is part of operating it safely.

Treat document HTML as untrusted

The CLI preserves original HTML rather than sanitizing or rewriting it. Published documents render inside an opaque-origin iframe with allow-scripts only. Response CSP controls resource loading, and escaped metadata keeps titles and file names from becoming viewer markup.

The sandbox prevents access to the viewer DOM and same-origin storage and omits popup, top-navigation, and form permissions. It does not prevent allowed script from consuming CPU or memory or navigating its own preview frame. Static validation cannot reliably detect every URL assembled by script.

Responses default to no-referrer, but author markup or script can override that policy or place data directly in a destination URL. Supported third-party CDN scripts can observe resource requests and remain a supply-chain dependency. Read HTML compatibility for what the served policy allows.

Do not open stored document HTML directly in a browser from disk. That bypasses the served response headers and CSP.

Choose a live-reader boundary

Mode Reader access
Loopback First-start default on 127.0.0.1. Processes and people able to reach your local account's viewer can read the library.
LAN Every device able to reach the selected HTTP port can read the full live library. No login, password, or token.
Tailscale HTTPS through the existing client, with reader access governed by your tailnet policy. No public Funnel is enabled.

Host validation checks the configured addresses and explicit trusted tailnet hostname. It does not authenticate a reader. Forwarding or Tailscale identity headers grant no access. All reader routes remain read-only; administration stays in the local CLI.

Public /health exposes only anonymous success. Process readiness and identity are restricted to a separate secret loopback control URL stored in private local records. Do not copy those records into a public site or share control URLs.

Know where data lives

The default inbox is ~/.html-inbox. HTML_INBOX_HOME selects another library. Original HTML is stored at documents/<id>/index.html and metadata at documents/<id>/metadata.json.

The inbox also contains saved viewer configuration, process records, logs, identity and startup locks, optional Tailscale ownership, and optional remote state. Remote records contain capability secrets; temporary snapshot work can contain the complete library. Treat them as sensitive even when the reports themselves are public.

On POSIX filesystems that enforce permissions, managed directories use 0700 and files use 0600. Existing managed paths are tightened when accessed. Symlink and regular-file checks protect managed paths, and the process records have additional descriptor and link-count checks.

These protections do not encrypt content, change existing ownership recursively, or protect against privileged administrators and processes running as the same account. A filesystem that ignores Unix mode bits cannot provide the POSIX privacy guarantee.

Prepare Windows storage

The installed CLI and ordinary viewer work on Windows. Node's Unix mode calls do not install or verify owner-only Windows ACLs. Privacy depends on existing and inherited filesystem ACLs, including those on files moved into the inbox.

  1. Choose a protected local NTFS directory under your user profile. Avoid public, shared, network, or synced locations for sensitive reports.
  2. Before first use, create the directory and inspect Properties, Security, Advanced. Keep access for your account and trusted system or administrator accounts. Remove broad grants such as Everyone, Users, or Authenticated Users, including unwanted inherited grants.
  3. Apply the intended restrictions to files and subdirectories. Inspect existing content, disabled inheritance, and permissive explicit child grants. Recheck after a restore or move.
  4. Protect separate export paths and their parents. Remote operations also need protected operating-system temporary storage for short-lived Wrangler logs.

For a custom PowerShell inbox, set the environment and inspect both root and child ACLs. These commands display permissions; they do not repair them. 

$env:HTML_INBOX_HOME = Join-Path $env:LOCALAPPDATA 'html-inbox'
icacls "$env:HTML_INBOX_HOME"
icacls "$env:HTML_INBOX_HOME" /T

Resolve inspection errors before using sensitive content. icacls /verify checks ACL structure, not confidentiality. The complete Windows prerequisites explain inheritance and the affected paths.

Back up and restore deliberately

Back up the complete selected inbox to preserve documents, metadata, configuration, and remote intent. Keep the backup as private as the original. Stop the viewer and any remote command or automation first so your copy is not racing file changes.

Do not run an old active process record or copy locks as evidence that a process is alive on another machine. During restore, keep original HTML and metadata together. Review startup records and retained Tailscale or remote ownership before using a restored library; follow recovery guidance rather than deleting journals to bypass safety checks.

Restoring remote capabilities can reintroduce sensitive bearer information. Recheck Windows ACLs throughout the restored subtree. A backup on an open share or synced folder can expose the complete library.

Understand static snapshot privacy

Static capabilities contain 128 random bits and the site root has no inbox listing. They are bearer secrets, not authentication. Anyone with the full path can read and reshare all published documents.

Production revoke rotates away from the old route but does not erase immutable deployment history or recipient copies. The Cloudflare account ID is not secret; credentials come from Wrangler's login store or CLOUDFLARE_API_TOKEN and are not written into HTML Inbox remote state.

Know the unsupported guarantees

HTML Inbox does not provide multi-user roles, recipient authentication, fine-grained document permissions, synchronization, malware scanning, guaranteed secret-link confidentiality, or guaranteed erasure. It does not fully contain navigation by allowed document scripts or in-frame resource exhaustion.

See the threat model and architecture for the source-level security boundaries.
