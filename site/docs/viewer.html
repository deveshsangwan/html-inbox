HTML Inbox documentation

Run the live viewer

The viewer serves the current local library and runs in the background by default. Every reachable live reader can read and permanently delete individual documents. Publishing and process control stay in the CLI.

Live UI deletion requires a reader running 0.5.x. The skill fallback stays pinned to published 0.4.0, with copy and named-inbox support but no UI deletion. Before an authorized upgrade, review the 0.5.0 permission change and saved exposure and hub mounts.

Read with more document space

Mobile and desktop use the same compact document toolbar. Back returns to the searchable inbox; the details menu holds the filename, type, and date. Choose Hide frame to give the document the available browser area, then use the small Show frame button to restore the toolbar. The document stays loaded and preserves its scroll and interactive state. Browser controls remain visible.

Delete one document

Choose Delete from a live inbox list row's three-dot menu or the document options menu. The confirmation shows the title, filename, and inbox, explains permanent deletion, and defaults to Cancel. Confirming removes the stored document from its original inbox. There is no Undo or bulk deletion. The original source file, existing exports, and remote snapshots remain unchanged.

Deletion is enabled by default on loopback, LAN, and Tailscale, without a startup grant or reader login. The network you choose determines who can read and delete documents. Every reachable live hub reader can delete from every mounted inbox; source filters do not restrict that authority. A hub binds each source's deletion writer to its captured canonical root, inbox UUID, and filesystem identity under the same OS account.

If a source is unavailable or replaced, deletion fails without recreating it or choosing another target. Deletion first moves the record out of the live library, then purges its files. If purge fails, the document is already absent and the cleanup failure is reported. Static exported and hosted snapshots are read-only independent copies with no live deletion controls or live viewer credentials.

Copy text and code

In version 0.4.0 or newer, open Viewer options, then choose Copy content.... Copy all saved document text, select a portion and choose Copy selection, or switch to Code blocks and pick a numbered block. Copying uses plain text and preserves code spacing. The preview stays loaded while the dialog is open.

Text comes from saved HTML. Scripted changes, edited form values, and chart visuals may be missing; CSS-hidden text can remain. For a selection in the current preview, use your browser's keyboard, context menu, or touch Copy.

If automatic copying is unavailable or denied, choose Select all and use your device's Copy command. This also works with ordinary HTTP LAN readers. Copying changes the reader's clipboard without changing an inbox. Named viewers, the live hub, and new static snapshots share these controls.

If text stays fully selected after Select all, close and reopen the dialog before selecting a smaller portion.

Copying uses saved HTML rather than the live rendered page. HTML source, Markdown, and formatted HTML are not clipboard formats in this release. Restart an existing verified viewer after an authorized CLI update to load these controls. Static readers gain them only when their owner regenerates and publishes a snapshot. Loopback HTTP and valid HTTPS can offer automatic copying; ordinary LAN or tailnet HTTP may require manual Copy. Browser policy can deny writes even over HTTPS.

Preparation refuses invalid UTF-8 or copy JSON exceeding 10 MiB without truncating text or disabling the preview. This output limit is separate from HTML_INBOX_MAX_BYTES. If preparation is unavailable, use native Copy in the preview; manual dialog Copy needs successfully prepared text.

Choose appearance

System is the default. Choose Light or Dark to override it for this browser. The inbox, toolbar, and supported documents follow the choice. Selecting System follows this device's OS. Browser choices persist on the same origin and device; they do not sync to other readers or the CLI.

Set the initial preference for readers without a browser override:

html-inbox preferences --appearance system
html-inbox preferences --appearance dark
html-inbox preferences --json

The CLI saves the default in preferences.json under the selected inbox home. New static exports capture it when created. Older CLIs, including 0.2.0, lack this command. Check html-inbox --help before using it.

New skill-generated documents include both themes. Existing documents with hardcoded colors may need individual adaptation. Images, chart colors, and intentional white paper previews keep their authored appearance. Hiding the frame does not change the document theme.

Start in the background

html-inbox viewer

The command starts a detached process or reuses the viewer for this inbox. It returns after a private readiness check and prints a usable inbox URL. The process survives terminal closure. publish uses the same startup path and returns a document URL for the active exposure.

Detachment does not escape an agent's systemd scope or provide automatic restart. Stopping that scope also stops its viewer. Use an explicit boot service for links that must survive agent cleanup, logout, or reboot.

First startup binds 127.0.0.1 on port 3217. The last successful port, address, and exposure are saved in the selected inbox. Later starts and publishing reuse them, even after viewer stop.

Select the inbox and port

Use --inbox NAME, absolute --home, or a process binding such as HTML_INBOX_NAME / HTML_INBOX_HOME to choose a library. Keep that selection consistent across publishing, status, stop, and service commands. A relative path resolves against the current directory, so an absolute path is clearer for automation. 

HTML_INBOX_HOME=/home/alice/inboxes/reports html-inbox viewer --port 4321

--port overrides HTML_INBOX_PORT. An explicit environment port overrides the saved port. Valid CLI ports are integers from 1 through 65535. Without either override, the saved configuration applies, or port 3217 on first startup.

Registered entries without a binding or default require a one-operation choice in a fully interactive terminal. Redirected streams, scripts, and JSON mode fail with selector guidance. With no entries or binding, legacy first use remains. See selection rules.

Keep it attached

html-inbox viewer --foreground

Use foreground mode for debugging, containers, or your own service manager. It stays attached and reports errors in the terminal. Stop it with Ctrl-C. A foreground start refuses to take over an already running viewer; stop the existing process first.

The detached child runs foreground mode internally. Repeated and concurrent background starts coordinate through the inbox startup lock. Process records and private control health identify the inbox and the specific viewer process before reuse or signaling.

Inspect and stop it

html-inbox viewer status
html-inbox viewer stop

Both commands print readable text in 0.3.0. Add --json for automation that previously parsed their default JSON. JSON status reports state, exposure, port, URLs, and a PID when verified. States include running, stopped, conflict, and incompatible. A reported URL is usable only when the state is running.

Stop checks the private process record against control health before sending a signal. It waits for shutdown and verified Tailscale cleanup when needed. A conflicting service, mismatched inbox, older control protocol, or unverified process is refused. The CLI does not kill a process solely because its PID appears in a saved record.

status and stop do not accept startup flags. Omit HTML_INBOX_PORT to use the saved active port, or keep its explicit value consistent with the viewer you intend to manage. 

html-inbox viewer status --inbox development --json
html-inbox viewer stop --inbox development --json
html-inbox inbox list --running

Catalog inspection includes only registered sources and verifies running viewers privately. It does not discover every listener. Use a local hub to read explicitly selected libraries together without starting their standalone viewers.

Change reader exposure

Choose one of --loopback, --lan, or --tailscale. Stop the current viewer before changing its exposure, port, or host. 

html-inbox viewer stop
html-inbox viewer --lan

To return to loopback, stop it and start with --loopback. That choice also replaces the saved exposure. 

html-inbox viewer stop
html-inbox viewer --loopback

LAN access exposes the entire live library over HTTP to every reachable reader. Tailscale access uses HTTPS Serve and your existing tailnet policy. Every reachable live reader can delete documents in either mode. Publishing, process control, and service management have no reader HTTP endpoints.

Find lifecycle diagnostics

Detached startup writes diagnostics to viewer.log inside the private inbox. Failed startup reports that path. The default reader's /health returns only {"ok":true}; it is not a process identity check. The separate secret loopback control URL belongs in protected local records and should not be shared.

Starting with 0.2.2, graceful shutdown records its timestamp, viewer PID, and first reason: SIGTERM, SIGINT, reader-close, or startup-failure. A stopped record follows successful cleanup. A signal record cannot identify who sent it; correlate the PID and timestamp with the service manager's journal. A forced kill or power loss may leave no shutdown record. Restart an existing viewer after updating the CLI to load these diagnostics; older compatible 0.2.x viewers may lack them.

See viewer troubleshooting for port conflicts, old records, and failed startup. Boot-manager logging differs; see service diagnostics.
