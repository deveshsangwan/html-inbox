Name libraries and read them together

Version 0.3.0 adds independent named libraries, a terminal picker, and a local reading hub. Naming a library records its location without moving or combining documents. Hubs support the same machine and OS account.

Name an existing or new library

html-inbox inbox register home --home /absolute/path/to/existing-inbox
html-inbox inbox create development --home /absolute/path/to/development-inbox
html-inbox inbox list
html-inbox inbox list --running --json

Register preserves an existing library; create initializes a new root. Unknown names during ordinary commands never create libraries. Names use 1-63 lowercase letters, digits, underscores, or hyphens, start with a letter or digit, and exclude reserved filenames. Each binding captures a canonical absolute home and durable UUID. Missing or replaced homes fail instead of being adopted. The catalog defaults to ~/.config/html-inbox, independent of the selected library.

List shows registered names, viewer states, and running reader URLs. --running filters to privately verified running viewers; anonymous reader health is not verification. Stopped libraries stay registered. Unregistered libraries are not discovered. Catalog and picker inspection do not create source paths or repair permissions.

Select one destination per operation

html-inbox publish ./report.html --title "Build report" --type report --inbox development
html-inbox list --inbox development --json
html-inbox viewer status --inbox development --json
html-inbox viewer --inbox development --port 4321

Library commands choose explicit --inbox / absolute --home, then process-bound HTML_INBOX_NAME / HTML_INBOX_HOME, then the configured default. An explicit selector overrides the entire environment tier. A name and home in one tier must match. Invalid names, stale defaults, and changed identities fail without falling back. Relative HTML_INBOX_HOME keeps its legacy meaning relative to the current working directory.

With entries and no binding or default, the picker requires stdin, stdout, and stderr all attached to TTYs and no --json. Enter an exact name or #N row, such as #2. Numeric names remain exact names. Use :q, Ctrl-C, or EOF to cancel. Even one entry requires a choice, which applies to this operation only and never saves a current inbox or changes the default.

Redirecting any stream disables the picker. Scripts, agents, pipelines, and JSON mode fail with available names and selector guidance on stderr, leaving stdout empty. Keep an intended selector or binding across every command. Ask which library to use if it is unknown. With no entries or bindings, legacy first use at ~/.html-inbox remains. 

export HTML_INBOX_NAME=development
html-inbox list --json
html-inbox inbox default home
html-inbox inbox default --clear

In PowerShell, use $env:HTML_INBOX_NAME = 'development'. A default affects future unbound operations; an environment binding still takes priority. Clear or set a healthy default deliberately to repair an unavailable one. Use explicit selection to reach a healthy library during recovery. Library ports must differ. Naming preserves preferences and saved exposure; stop a verified viewer before changing its active port, host, or exposure. Restart to load a new named heading.

Read explicit libraries through a hub

html-inbox hub init --config /absolute/path/to/reading-hub.json \
  --name "My reports" --inbox home --inbox development
html-inbox hub --config /absolute/path/to/reading-hub.json --port 4322

Init requires an existing canonical parent directory and refuses an existing config. It captures 1-128 explicit name/home/UUID mounts. New catalog entries and default changes never add sources. Membership stays fixed for the running hub; review a new config deliberately when it should change. Protect the config and parent because it contains local paths.

The hub runs in the foreground until Ctrl-C. Its default listener is loopback port 3218. It combines list and search with inbox badges and a source filter. Source names keep identical document IDs distinct. Missing, mismatched, or corrupt sources mark results incomplete while healthy sources remain readable. Public notices omit local paths and control details; operator diagnostics go to stderr.

Source viewers may be stopped. Hub reads check existing source files without creating paths, tightening permissions, writing preferences, or copying runtime state. POSIX sources must belong to the current account. Windows ACL privacy remains a prerequisite for every source, the catalog, and config. Read-only inspection does not repair ACLs. See Windows storage prerequisites. Hub document reads use HTML_INBOX_MAX_BYTES, default 10 MiB. 

html-inbox hub --config /absolute/path/to/reading-hub.json \
  --lan --host 192.168.1.20 --port 4322

Every reachable hub reader can read every selected library, even if its standalone viewer is stopped or private. Filters are reading aids, not access control. Source viewers and hubs accept HTTP GET and HEAD only, with the existing sandbox, CSP, and Host checks. Publishing and deletion remain local CLI operations. Hubs do not manage source lifecycles, Tailscale Serve, or boot services. Cross-account reading, network replication, remote ingestion, and historical-fragment migration are outside this release.

Select a library for a boot service

Service commands use the invoking account's catalog. Resolve the normal user's intended absolute home before sudo, then use --home or HTML_INBOX_HOME consistently for install, status, and uninstall. Named libraries retain the single fixed boot-service definition per machine. Use deliberately installed stable Node and CLI paths. See boot setup and ownership.

Upgrade humans and agents from 0.2.x

Stop an old viewer with the executable that started it, or Ctrl-C for foreground mode, and confirm shutdown before updating. For boot startup, uninstall with the old installation, update, then reinstall with the intended home and exposure. Versions 0.2.x and 0.3.x share protocol 3; restart compatible viewers to load the new code. Incompatible 0.1.0 viewers still require their original executable for shutdown. Documents, preferences, and saved exposure persist. Follow the CLI update and service update instructions.

  • Add --json to viewer status/stop and service commands when parsing output. They print readable text by default in 0.3.0. Document and catalog lists are readable tables. Plain publish, detached viewer startup, and hub startup keep URL-only stdout. publish --json returns url, inbox, and home.
  • Bind automation before registering a library. Even one entry makes unbound redirected jobs fail rather than choose the legacy home. Use --inbox, absolute --home, an environment binding, or a deliberate default. No entries preserves legacy behavior.
  • Update skills separately. The skill accepts stable installed 0.2.x and 0.3.x CLIs and keeps its fallback on published npx --yes html-inbox@0.2.2. That fallback lacks named selection, hubs, the picker, publish JSON, and new viewer/service JSON flags. Check actual help for each capability, including inbox list --running. Older viewer and service commands already output JSON without the new flag. Preserve the intended destination when a feature is unavailable.
  • JSON never prompts or grants destructive approval. Deletion still requires --force; remote revoke requires --yes.

The CLI resolution reference defines exact resolver acceptance and the published fallback pin. The source guide covers identity validation, interrupted registration, and service compatibility. See the CLI reference for complete syntax.
