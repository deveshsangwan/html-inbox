HTML Inbox documentation

Publish and manage documents

HTML Inbox stores the original HTML and separate metadata. Publishing and deletion are local CLI operations, including when readers use LAN or Tailscale.

Publish a file

html-inbox publish ./report.html \
  --title "Quarterly migration report" \
  --type report

The file must be a regular UTF-8 .html or .htm file. The CLI requires both --title and --type. Type is a label you choose, such as report, note, or dashboard; it does not select a renderer.

Field Limit
Title 1 to 200 characters; must contain non-whitespace text.
Type 1 to 64 characters; must contain non-whitespace text.
Source file name At most 255 characters. Taken from the file path.
HTML file 10 MiB by default, or the positive byte limit in HTML_INBOX_MAX_BYTES.

Publishing validates input and ensures a healthy viewer before adding the new record. The command prints a document URL on stdout. Compatibility warnings go to stderr and do not prevent storage. An invalid file or failed viewer startup returns an error.

Each publish creates a new ID, including when the title or file name matches an earlier document. To replace a report, publish the revised file, check its new URL, and delete the previous ID deliberately.

Use generated HTML

Start with the repository's sample report, support dashboard, or Mermaid diagram. Save the linked source as a .html file, then publish it with a title and type. These complete examples differ from the fictional previews on the landing page. The Mermaid example needs internet access for its supported CDN library.

Ask your generator to produce one complete HTML document with embedded CSS and assets. Save it as a file, then publish it. Sibling asset files are not copied. 

your-generator > report.html
html-inbox publish ./report.html --title "Generated report" --type report

your-generator is a placeholder for your own tool. HTML Inbox does not read publish input from stdin and does not accept a JSON publish request. A generator that returns JSON must first extract its HTML field into a .html file.

For a report with interactive controls, attach events from an inline script. Inline onclick attributes are blocked. See HTML compatibility for embedded images, Tailwind, Mermaid, and navigation.

Browse and search

html-inbox viewer
html-inbox list

Open the inbox URL from viewer. The live viewer searches document title, type, and source file name. It does not perform full-text search of document HTML. The browser has no publish, delete, or process-management controls.

The plain-text list contains tab-separated ID, type, creation time, and title. JSON includes the complete stored metadata. 

html-inbox list --json

Delete a document

Copy its ID from list, then run the delete command. Confirmation defaults to no. 

html-inbox delete <document-id>

For automation, use --force. --json changes successful output to JSON with the metadata and reclaimed byte count; it does not remove the confirmation requirement. 

html-inbox delete <document-id> --force --json

Deletion removes the local record from the live library. It does not update an existing static export or Cloudflare deployment. Run remote publish to replace the remote snapshot with the current library, and consider historical deployment limits before assuming older content is inaccessible.

Use output in scripts

Capture the publish URL from stdout. Keep warnings visible on stderr so you can spot blocked resources. 

html-inbox publish ./report.html --title "Daily report" --type report > report-url.txt
html-inbox list --json > documents.json

publish has no --json option. list, delete, export, and remote commands support --json. Viewer and service status commands already print JSON without a flag. CLI errors return a nonzero exit status. A status command can succeed while reporting a stopped, conflicting, incompatible, or failed state; inspect its JSON state before treating the viewer as ready.
